# 위험 작업 게이트

Work Manager 데이터 변경 중 **영향이 큰 작업**은 반드시 사용자 명시적 동의를 받은 뒤에만 실행한다. 일상 조회·단건 생성·메모 수정은 게이트 없이 바로 진행.

## 위험 작업 분류

| 카테고리 | 대상 동작 |
|---------|---------|
| **금액 변경** | 프로젝트 파트너 계약금/수금 금액 수정, 견적서 버전 내 품목 단가/수량 수정 |
| **상태 대량 이동** | 견적서 시리즈 상태 변경, 프로젝트 상태 일괄 변경 |
| **삭제** | 모든 DELETE (소프트 삭제여도 UI 표시/청구 흐름에 영향) |
| **청구 대상 변경** | `billingClientId` 수정 (대금 청구 상대가 바뀜) |
| **버전 생성** | 견적서 새 버전 생성 (청구 근거가 교체됨) |

## 게이트 프로토콜 (2단계)

### 1단계: Preview 출력

실제 API 호출 전에, **다음 내용을 주인님께 보고**한다:

- **무엇을 바꾸는지** (엔티티, ID/식별자)
- **어디서 어디로** (현재 값 → 새 값)
- **영향 범위** (예: "견적서 PDF 재생성 필요", "수금 차수 1건 추가됨")

예시:
```
[변경 미리보기]
대상: 프로젝트 "DDP 웹사이트 리뉴얼" (id: proj_abc)
수금 차수 1차 금액: 5,000,000원 → 5,500,000원
세금유형: vat (공급가액 기준)
영향: 총 수금액 + 500,000원, VAT 표시액 + 550,000원
```

### 2단계: 주인님 명시적 동의 대기

다음 발화 중 하나를 받기 전까지 fetch 실행 금지:
- "실행", "진행", "ㄱㄱ", "응", "해줘", "yes" 등 명확한 동의 표현
- 또는 변경 내용 자체를 재확인하는 응답

모호한 반응(예: 질문, 의견 추가)이 오면 **재확인 요청**:
> "위 변경안대로 진행할까요?"

### 3단계: 실행

동의를 받으면 curl 호출. 성공 응답(`success: true`) 확인 후 주인님께 한 줄 보고:
```
[완료] 수금 차수 1차 금액 5,500,000원 반영됨
```

## 게이트 **없이** 바로 실행해도 되는 동작

- 모든 GET (조회)
- 신규 메모 추가 (단순 텍스트, 금전 영향 없음)
- 단건 신규 생성 중 **금액 0 / 상태 초기값** 인 경우 (단, 생성 후 금액 수정은 위험에 해당)
- 이미 주인님이 직전에 구체적 값을 말한 경우 (예: "A고객 이메일 foo@bar.com 으로 수정해줘" → 이메일 수정은 게이트 불필요)

## 실수 방지 체크

쓰기 요청을 조립할 때 스스로 질문:
1. 이 변경이 **금전**·**상태 흐름**·**청구 대상**에 닿는가? → 게이트
2. 주인님이 **직접 수치/대상**을 언급했는가? → 게이트 생략 가능 (단 preview로 확정값만 한 번 읽어드림)
3. 실수로 잘못된 ID를 조립할 가능성이 있는가? → 게이트
